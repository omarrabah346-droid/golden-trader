# VEXORA V2 — حزمة مراجعة التنفيذ

الأساس هو الفرع `fix/vexora-p0-security` عند `fe9537b`. ملفات SQL في مجلد المراجعة وتطبق بالترتيب 001 ثم 002 في قاعدة اختبار معزولة. تحتاج بيئة المراجعة أدوار Supabase ودالة `auth.uid()` وحساب ترحيلات مخول بإنشاء الأدوار وتغيير ملكية الدوال. لا تتضمن الحزمة بيانات مالك أو خطط أو ربط حسابات فعلياً. تُرفض الإجراءات الإدارية إلى أن تُسجل هوية المالك بطريقة موثوقة.

## مراجعة المخطط

| المسار | المتاح في الفرع | المطلوب للاعتماد |
| --- | --- | --- |
| الحسابات | `supabase_setup.sql` يعرف `profiles` و`config` وRLS ودوال `is_admin` و`is_member` ومشغل `guard_profile`. تعريف role المحلي يقيّد القيم إلى member وadmin. | تعريفات الإنتاج الفعلية لـstaff والمالك والشريك وإدارة صلاحياتهم. اختيار UUID المالك وكيفية استعادته عند تبدل الحساب. |
| الدفع القديم والأكاديمية | استخدام `purchases` والتخزين ظاهر في `index.html` و`app.html`. مسودة إصلاح الإيصالات P0 معطلة في `docs/security`. | DDL وRLS والمنح وRPC ومسارات رفع وتحميل الإيصال وأي triggers تؤثر على العضوية. معرفة مصدر صلاحيات الكورسات والمشتريات مدى الحياة. |
| التسويق وAI | قيود واجهة في `marketing-workspace.js` واستدعاءات من المتصفح. | تعريف مزود AI ووظائفه وسياسات التسويق وفحص الصلاحيات لكل طلب خادمي. |
| Telegram وTradingView | العرض وحفظ بيانات المستخدم في واجهة الموقع. | إثبات ربط هوية Telegram الرقمية ومعرّف المجموعة وصلاحيات البوت، وتحديد الحساب والمؤشرات وطريقة تغيير صلاحية TradingView. |

## الصلاحيات والتوافق

يخصص الجسر الموثوق سجل enrollment للطالب أو الشريك حسب نموذج الحساب الفعلي، باستخدام معرف نسخة خطة ثابتة. تحدد الخطة مجموعة مستقلة من academy وvip وindicators وmarketing وai. خطة الاختبار للطالب تشمل الثلاث الأولى وللشريك التسويق وAI فقط. مصفوفة الإنتاج تنتظر موافقة المالك. يُفحص الاستحقاق من جهة الخادم عند كل طلب محمي استناداً إلى الخطة ووقت البداية والانتهاء والسحب. توفر `vx_sub_v2_my_status` قرار الحساب المسجل دخوله كمصدر لواجهات V2. إظهار الميزة في المتصفح لا يكفي لإتاحة بياناتها.

تبقى مسارات الدفع القديم على كودها الحالي. عند الدمج لاحقاً، يُحدد المسار القديم أو V2 وفق مجموعة تفعيل موثوقة لكل مورد. يجب أن يرفض المسار V2 فتح مزية انتهى اشتراكها حتى إذا استمر دور الحساب أو العضوية القديمة. تحتاج المشتريات السابقة والمزايا المستقلة إلى قواعد مكتوبة قبل نقل أي حساب. الحزمة لا تربط الواجهات الحالية ولا تغيّر أي جدول قديم. الربط بين سجلات تسوية الدفع القديم وV2 مطلوب لفرض منع إعادة استخدام دفعة سبق اعتمادها خارج V2.

## الإيصالات والمدفوعات

يودع خادم موثوق الإيصال في تخزين خاص بعد التحقق من جلسة الرافع وملكية الطلب ونوع الملف وحجمه. يستدعي الخادم عملية الربط باستخدام جلسة خدمة. يستخرج خادم التوقيع مفتاح الإيصال عبر RPC بهوية المالك ثم يصدر رابطاً قصير العمر. يلزم اعتماد سياسة التخزين والتنظيف والاحتفاظ. مراجعة التحويل تتطلب مطابقة سجل التسوية الفعلي والمبلغ والعملة. مفتاح التحويل معياري بصيغة rail:namespace:event مع قواعد كل مزود. قيد قاعدة البيانات يمنع تكرار المفتاح عبر حسابات V2. يجب اعتماد التطبيع وربط المراجع المتعددة التي تشير إلى نفس التسوية قبل التفعيل.

تُحسب الشهور تقويمياً في UTC وفق التصميم. يعتمد السحب على قرار المالك ويحفظ سجل الدفع. يظل الاشتراك المسحوب تحت المراجعة وتحتاج إعادة تفعيله أو تبديل الخطة قراراً صريحاً.

## مهام المنصات الخارجية

تنشئ الموافقة والتجديد والسحب مهام فورية وتجدول مهام عند الانتهاء لكل مزود. تعرض دالة المالك المهام المستحقة للإصدار الحالي وتحسب الوصول المرغوب من الحالة الحالية والخطة. يسجل المالك نتيجة المحاولة، ويراجع النظام الوصول المرصود. تبقى المحاولة الفاشلة قابلة للإعادة. إذا تغير الإصدار أثناء الإجراء، تُسجل النتيجة كمهمة متجاوزة ويضاف تحقق جديد. التشغيل يدوي حتى اعتماد ربط الهوية والتكامل. قبل أتمتة Telegram يلزم عامل بمهلة تنفيذ وإعادة محاولة محدودة، وتحقق من صلاحية الجلب ومطابقة العضوية، ومراجعة تضارب العضويات المدفوعة القديمة. TradingView يحتاج تأكيد منح الصلاحية أو سحبها من المالك. يتوقف الوصول الداخلي فور الانتهاء، أما الوصول الخارجي فيتبع زمن تنفيذ المهمة.

## الاختبارات المحلية

اختبار التصميم الحالي عبر `node --test tests/design/vexora-subscriptions-v2.test.mjs`. اختبار قاعدة البيانات عبر `node --test tests/subscriptions-v2/postgres.test.mjs` بعد إنشاء عنقود PostgreSQL منفصل باسم `vexora-subscriptions-fixture`، وقاعدة `vx_sub_test`، ودور محلي `vx_test_admin`. يستخدم الاختبار `VX_SUB_TEST_PORT` ضمن نطاق 56xxx، و`VX_SUB_TEST_PSQL` لمسار psql عند الحاجة، و`VX_SUB_TEST_SOCKET` لمسار المقبس المحلي الاختياري. يمكن استخدام النسخة نفسها لاختبار جلسات متزامنة فعلية. تُقرأ هوية العنقود والقاعدة قبل إجراء أي تعديل. تُنشأ قاعدة جديدة لكل إعادة تشغيل كاملة.

## نتيجة مراجعة هذه الحزمة

- التحقق المعتمد لهذه التسليمة يقتصر على اختبارات Node.js وفحص صياغة JavaScript. اختبارات التصميم محاكاة لقواعد الدفع.
- اختبارات PostgreSQL متعددة الجلسات وRLS الشاملة وSupabase الفعلي مؤجلة. توجد ملفات تجهيز اختبار حقيقية ببيانات اصطناعية، ولا تسجل الحزمة نتيجة نجاح لها.
- وحدة `subscription-client.mjs` تربط طلب الاشتراك وحالة المزايا بواجهات RPC. لوحة المالك وحدة مستقلة تنتظر تركيبها ضمن جلسة المالك وخادم توقيع الإيصالات. يظل فرض الصلاحيات على نقاط الوصول الحالية معلقاً حتى مراجعة التعريفات الفعلية.
